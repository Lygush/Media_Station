## 1. Версия из одного места (аудит §2.2 п.1, §0 п.8)

- Файл `app_version.txt` в корне (сейчас `1.1.0`) — единственный источник версии.
  Имя `VERSION` нельзя: на Windows оно перекрывает стандартный заголовок
  C++20 `<version>` (папка проекта есть в INCLUDEPATH, регистр не важен).
- `MediaStation.pro` читает его и: передаёт `MEDIASTATION_VERSION` в код,
  записывает ресурс `VERSIONINFO` в exe (Свойства → Подробно). При изменении
  `app_version.txt` qmake перезапускается сам.
- `Version.h` больше не правится руками; `UpdateManager` его подключает —
  раньше клиент всегда считал себя «1.0.0».
- Сервер (`UpdateTab`): версия читается из выбранного `MediaStation.exe`
  (`GetFileVersionInfo`), поле только для чтения. Если в exe версии нет
  (сборка до этого изменения) — поле, как раньше, вводится руками.

**Выпуск новой версии:** поменять `app_version.txt` → собрать → на сервере выбрать exe.

## 2. Ввод пульта в Android TV через консоль эмулятора (§1.2 D, §0 п.7)

- Стрелки, OK и «Назад» уходят в эмулятор командой консоли
  `event send EV_KEY:<код>:1 EV_KEY:<код>:0` (TCP `127.0.0.1:<порт консоли>`,
  токен из `%USERPROFILE%\.emulator_console_auth_token`). Нажатие попадает
  прямо в виртуальную клавиатуру — без запуска JVM в Android на каждую пачку
  нажатий (200–500 мс CPU гостя, рывки звука при листании).
- Остальные клавиши (Home, Поиск, Закладки) — как раньше, `input keyevent`.
- Любой сбой консоли (нет соединения за 3 с, токен не найден/отвергнут,
  три отказа `KO` подряд) — автоматически старый путь до следующего запуска
  ТВ, с записью в `Android_TV.log` (`[Input] emulator console unavailable …`).
- Переключатель в профиле: «Быстрый ввод с пульта (консоль эмулятора)»,
  по умолчанию включён. **Если стрелки/OK в ТВ перестали работать —
  выключить его** и написать, что в журнале.

Коды: ↑103 ↓108 ←105 →106, OK 232 (KEY_REPLY = DPAD_CENTER в раскладках
Generic.kl и qwerty.kl), Назад 158.

## 3. Неудачный запуск игры и меню питания (§11 п.2, п.5)

- При `launchFailed` показывается уведомление «Игра не запустилась: …»
  с понятной причиной (раньше — только `console.warn`, «ничего не произошло»).
  Для этого у `NotificationModule` появился `post(...)` для QML — текст
  переводится на стороне QML (§13 п.12).
- Меню питания: **Выход / Сон / Перезагрузка / Выключение**.
  Выключение и перезагрузка: программа закрывается обычным путём (модули
  завершают эмулятор через `emu kill`, DS4Windows, хуки), затем `main()`
  вызывает `ExitWindowsEx` (с включением привилегии SE_SHUTDOWN_NAME;
  запасной путь — `shutdown.exe`). Сон — `SetSuspendState` без выхода.
  Новые иконки `ic_restart.png`, `ic_sleep.png`.
- Кнопка «Меню» на пульте теперь открывает/закрывает меню питания (раньше
  ставила `visible = true` уже видимому элементу и ничего не делала).

## 4. Описание игры (§18 п.1–4)

- Выбранный пользователем appId передаётся в `GameInfoFetcher::fetch`:
  страница Steam, локальная база и поиск в Wikipedia идут по выбранной игре
  (Wikipedia — по точному названию из Steam). Раньше текст мог быть от другой игры.
- `TitleNormalizer`: подзаголовок после «: » больше не отрезается
  («Star Wars Jedi: Fallen Order», «Batman: Arkham City»); вариант без
  подзаголовка пробуется вторым, если по полному ничего нет.
- Римские цифры: только заглавные, только последним словом, от двух букв
  («I Am Bread», «Mega Man X», «Divinity ii» не трогаются; «Final Fantasy VII» → 7).
- Второй запрос описания, пока нейросеть занята, — уведомление «Нейросеть
  занята описанием другой игры», а не молчание.
- Тест `tst_titlenormalizer`.

## 5. Шейдер дымки (§17)

- Дымка считается в текстуре вдвое меньшей по каждой стороне
  (`layer.textureSize`) — в 4 раза меньше работы шейдера. Слой ещё и
  кэшируется: при анимациях интерфейса (не дымки) шейдер не пересчитывается.
  Взято ½, а не ¼, как предлагал аудит: тонкие струйки (σ ≈ 0,4 % высоты)
  при ¼ становятся уже пикселя.
- Верхние 36 % экрана — сразу прозрачный пиксель (там всегда ноль).
- Шум устойчив к долгой работе: номер клетки по модулю 289, время — по
  часам с заворотом раз в 3 часа (раньше `+0.033` за срабатывание таймера:
  при подтормаживании дымка замирала, а через десятки часов узор «рябил»).
- `FrameAnimation` **не** используется сознательно: она перерисовывала бы
  всё окно с частотой экрана (60–144 Гц) вместо ~30 раз в секунду.
- `.qsb` пересобраны (qsb 6.4 — формат читается всеми Qt 6.4+; HLSL для
  Windows на месте). Сборка шейдеров: `scripts/build_shaders.bat [qsb.exe]`
  (или `.sh`) — запускать после правки `mist.frag`/`mist.vert`.
- Удалена `assets/shaders/mist/backup/`.

## 6. Навигация стрелками пульта (§11 п.1, бэклог «стрелки в диалогах»)

`modules/AppModule/RemoteNavigator.*` (C++), подключён в `main.cpp` как `RemoteNav`.

- Пространственная навигация по тому, что уже кликается мышью: видимые и
  доступные `MouseArea`, кнопки Qt Quick Controls, поля ввода. Не нужно
  размечать каждый из ~50 QML-файлов.
- Стрелка выбирает ближайший элемент в этом направлении; элементы того же
  ряда/столбца в приоритете. Курсор переносится на его центр — работает
  обычная подсветка наведения; вокруг — рамка фокуса цвета акцента (Main.qml).
- **OK/Enter** — щелчок в центр выбранного элемента (через
  `QWindowSystemInterface`, тем же путём, что настоящая мышь). Кнопка ОК
  аэромыши, как и раньше, — обычный щелчок.
- Первое нажатие — рамка на элемент под курсором (и сразу шаг) или на
  ближайший к курсору.
- Слои: открытый диалог (`BaseDialog`), контекстные меню, меню питания и
  всплывающие окна Controls помечены `navModal` — навигация только внутри
  них. Подложки на весь экран, скрытые, выключенные и обрезанные прокруткой
  элементы не выбираются.
- Вверх/вниз, когда в этом направлении ничего нет, — прокрутка экрана, как
  раньше (так открываются плитки за краем).
- Влево/вправо при фокусе в поле ввода двигают курсор в тексте; Enter в
  поле ввода не превращается в щелчок.
- Движение мыши (аэромыши) больше чем на 12 px убирает рамку.
- «Назад» сначала закрывает меню питания и окно подтверждения.
- Разметка, если понадобится: `property bool navModal: true` (слой поверх
  всего), `property bool navSkip: true` (не выбирать элемент и потомков),
  `property bool navFocusable: true` (выбирать нестандартный элемент).
- `MediaStation.pro`: `QT += gui-private` (заголовок `qpa/qwindowsysteminterface.h`;
  в стандартной установке Qt он есть, qmake выведет предупреждение о
  приватных заголовках — это ожидаемо).
- Тест `tst_remotenavigator` (сетка, края, обрезка, модальный диалог,
  щелчок, сброс мышью) и сценарии `19_nav_*` на стенде.

Не сделано в навигации: геймпад (DualShock) в меню не отправляет стрелки —
это настройка DS4Windows (D-pad → клавиши) или отдельная работа в
`JoystickModule`; контекстное меню плитки по-прежнему открывается удержанием
(с пульта — только аэромышью).

## 11. Исправления после первой сборки (06.11)

- **Ошибка C2059 при сборке MSVC.** Файл версии `VERSION` в корне проекта на
  Windows (регистр в именах не важен) перекрывал стандартный заголовок C++20
  `<version>`: папка проекта есть в INCLUDEPATH. Файл переименован в
  `app_version.txt`; старый `VERSION` нужно удалить (`cleanup_pack2.bat`).
- **Esc в Android TV снова открывает оверлей.** Esc ловила только горячая
  клавиша в QML (`Main.qml`), а она срабатывает, лишь когда фокус клавиатуры у
  окна MediaStation. После того как `WS_EX_LAYERED` стал ставиться только на
  время показа ТВ, фокус при показе, видимо, перестал надёжно доставаться
  MediaStation. Теперь Esc в режиме ТВ перехватывает глобальный хук
  (`G72KeysModule`) и обрабатывает как кнопку «Меню» пульта: открыть/закрыть
  оверлей, от фокуса не зависит. Вне режима ТВ Esc работает как раньше
  («Назад»).
- **Обложка плитки после «Получить информацию»** не обновлялась до повторного
  входа на экран: плитки читают `game_info.json` только при загрузке экрана.
  Теперь `DynamicScreen` слушает `GameMediaModule.mediaFetched` и сразу ставит
  плитке новую обложку; к адресу добавляется `?v=…`, чтобы не показалась
  старая картинка из кэша, если новая записана в тот же `cover.jpg`. Сценарий
  стенда `20_cover_refresh`.
