# Изменения 04.11.2026 — Updater, UpdateManager, JoystickModule

Все правки проверены `clang++ -fsyntax-only -Wall -Wextra` (Qt 6.4, Linux) вместе с `moc`.
Windows-ветки (`#ifdef Q_OS_WIN`) компилятором **не проверялись** — их нужно собрать и
прогнать у себя (см. чек-лист в конце).

## Updater (`Updater/UpdaterWindow.*`)

| # | Проблема | Последствие | Исправление |
|---|----------|-------------|-------------|
| 1 | `moveDirectory()` безусловно удалял исходную папку, даже если часть файлов не перенеслась | Потеря файлов при нехватке места / отказе в доступе | Источник удаляется только при полном успехе |
| 2 | «Попробовать снова» после неудачного переноса делало `removeRecursively(m_oldDir)`, а там уже лежали перенесённые файлы (в т. ч. `data/`) | Безвозвратная потеря пользовательских данных | Сначала откат (`oldDir → targetDir`), `oldDir` больше не стирается |
| 3 | Если перенос `data/` не удался, `launchNew()` всё равно удалял `oldDir` — единственную копию данных | Потеря данных | Флаг `m_keepOldDir`: папка сохраняется, пользователю показывается путь |
| 4 | Нет проверки содержимого архива до замены рабочей версии | Старая версия удалена, новая без `MediaStation.exe` | Проверка `MediaStation.exe` в распакованном до `doReplace()` |
| 5 | `QApplication::quit()` до входа в `exec()` не срабатывает | После ошибки хэша окно Updater висело навсегда | `quitApp()` через `Qt::QueuedConnection` |
| 6 | Новый MediaStation запускался с CWD во временной папке, которую затем удаляли | Относительные пути, блокировка папки | `startDetached(..., workingDir=targetDir)`, CWD Updater сбрасывается перед очисткой |
| 7 | Отмена не чистила `MediaStation_New_*`, не сообщала, где остались данные | Мусор, потерянные данные | `onCancelClicked()` |
| 8 | `OpenProcess` вернул ошибку «нет доступа» → считалось, что процесс завершён | Замена файлов при работающем MediaStation | Завершённым считается только `ERROR_INVALID_PARAMETER` |
| 9 | Прогресс 7z парсился по `\n` (7z рисует через `\r`) | Прогресс отставал | Разбор по `\r`, `\n`, `\b`, берётся последнее значение |
| 10 | `fatal()` всегда писал «MediaStation не был изменён» и удалял архив | Ложная информация, нет повторной попытки | Архив удаляется только если он сам негоден; текст нейтральный |
| 11 | `GetLastError()` читался после логов/QDir | Неверная подсказка пользователю | Код сохраняется сразу |
| — | Подсказка «архив заново распаковывать не нужно», хотя он распаковывался | Путаница | Текст исправлен |

## UpdateManager

- После сбоя подготовки/запуска Updater кнопка обновления пропадала до перезапуска → теперь `m_updateReady` восстанавливается (кроме битого хэша).
- При неудачном `startDetached` восстанавливается рабочий каталог приложения (раньше оставался `%TEMP%`).
- Старые временные папки `%TEMP%\MediaStationUpdater\*` (копии Updater, которые он не может удалить сам) чистятся при старте, если старше суток.

## JoystickModule

- `shutdown()` теперь выставляет `m_stopping`, циклы ожидания DS4Windows и IPC-вызовы выходят сразу, и модуль **дожидается** фоновых задач. Раньше `cancel()` не останавливал уже запущенную задачу, она обращалась к удалённому `this`.
- `runCmdSync` ждёт короткими кусками (100 мс) и может быть прерван.

## Прочее

- `KaraokeModule`: `[=]` → явный список захвата (неявный захват `this` устарел в C++20).
- Порядок в репозитории: `ИСПРАВЛЕНИЯ.md` → `documentation/FIXES_2026-10-12.md`; `mediastation_fixes.patch` (356 КБ) удалён — его изменения уже в коде.

## Чек-лист проверки на Windows

1. Обновление «с нуля»: Updater дожидается выхода MediaStation, распаковывает, меняет папки, запускает новую версию, `data/` и `tools/android-tv/avd` на месте.
2. Обновление при открытой папке MediaStation в Проводнике (путь через file-by-file move) — `data/` не потеряна.
3. Архив без `MediaStation.exe` → понятная ошибка, старая версия не тронута.
4. Битый хэш → сообщение, после «ОК» процесс Updater **завершается**.
5. Закрыть MediaStation сразу после запуска (первые 5 секунд, пока стартует DS4Windows) → нет падения, DS4Windows остановлен.
6. После обновления текущий каталог нового процесса = папка приложения.

# Часть 2 — NetworkModule, TileManager, плитки установки

Проверено автотестом `tests/unit/tst_network_protocol` (настоящий TCP-сервер +
клиент, распаковка через 7z, сборка под AddressSanitizer/UBSan): **25/25**.
Тот же тест на исходном коде модуля: **10 провалов** — баги подтверждены.

## Установка по сети

| # | Проблема | Как проявлялось | Исправление |
|---|----------|-----------------|-------------|
| 1 | Плитка убиралась из UI только при явной отмене | Обрыв связи, нехватка места, ошибка записи или распаковки → плитка навсегда «устанавливается», после перезапуска — нерабочая плитка без пути | `cleanupClient()` — единая точка: всегда сообщает UI о незавершённой установке |
| 2 | Строка `PACK:` в одном TCP-пакете с JSON согласования разбиралась как JSON | Соединение рвалось, установка не начиналась | После диалога цикл согласования прерывается, остаток разбирается как фаза упаковки |
| 3 | Отключение отправителя во время распаковки убивало 7z и удаляло папку | Полностью принятая игра выбрасывалась | Архив уже принят — распаковка доводится до конца |
| 4 | После распаковки использовался «сырой» указатель на сокет | Ответ мог уйти другому клиенту (адрес переиспользован) | `QPointer<QTcpSocket>` |
| 5 | После `CANCEL` сокет не закрывался | Утечка соединений и буферов | Закрытие после удаления состояния клиента |
| 6 | Нехватка места обнаруживалась только в конце передачи | Гигабайты передавались впустую | Проверка места (временная папка + папка игр) до `READY` |
| 7 | Пустое название / `CON` / точка в конце → неверная папка | Установка в корень каталога игр или ошибка создания папки | `sanitizeFolderName()` |
| 8 | Занятый порт 12345/12346 при старте | Приём по сети молча не работал до перезапуска | Повтор каждые 10 с, запись в лог |
| 9 | Клиент, замолчавший на середине передачи, висел вечно | Открытый временный файл, «вечная» установка | Таймаут 60 с бездействия |
| 10 | Сигнал прогресса на каждый принятый кусок | Сотни обновлений QML в секунду | Не чаще раза в 100 мс |
| 11 | Две установки в одну миллисекунду писали в один временный файл | Повреждённый архив | Уникальное имя файла |

## Плитки (TileManager + DynamicScreen.qml)

- **Результат установки сохраняется в `structure.json` на стороне C++.** Раньше путь
  к игре записывал только открытый экран: если уйти с экрана во время установки,
  игра ставилась на диск, а плитка после перезапуска не запускалась.
- При неудачной установке удаляется только плитка без пути — неудачная
  переустановка больше не стирает рабочий ярлык.
- При загрузке экрана удаляются «мёртвые» сетевые плитки (прерванные выходом
  из программы), живая установка не трогается (`NetworkListener.hasActiveInstall`).
- Экран, открытый во время приёма, сразу показывает плитку в состоянии установки.

## Отправка логов

- Сторожевой таймер 30 с: если сервер принял соединение и замолчал, ошибка
  показывается вместо бесконечного «Ожидание сервера…».

## Как запустить тест

```
cd tests/unit/tst_network_protocol
qmake tst_network_protocol.pro && make   (или nmake / mingw32-make)
```
Рядом с exe нужен `tools/7zr.exe` (или 7z в PATH), порт 12345 должен быть свободен.

# Часть 3 — остальные модули, ядро, тесты, репозиторий

## Проверка

- Компиляция всех исходников: Linux (clang, `-Wall -Wextra`) и **Windows-ветки**
  кросс-компилятором MinGW — 0 ошибок и предупреждений (кроме `G72BatteryModule`:
  WinRT, только MSVC).
- Тесты: из 9 наборов собирался 1. Теперь все собираются через `tests/tests.pro`

## Исправления

### Установка и библиотека игр
| Проблема | Последствие | Исправление |
|---|---|---|
| Пустой путь установки (по умолчанию) — каждый модуль понимал по-своему | Библиотека игр **пустая**; «удалить вместе с файлами» не находил папку игры | `SettingsManager::installPath()` возвращает `<app>/data/games`, если не задан |
| `resolveInstallFolder` при ненайденной папке возвращал первую попавшуюся | Мог указать на **чужую игру** | Удалён (не использовался) |
| Рекурсивное удаление без проверки | Битый путь в данных → удаление чужой папки | `isManagedGameFolder()` перед удалением (InstallManager, GameLibrary) |
| Ошибка чтения при копировании считалась успехом | Повреждённая установка без сообщения | `copyFileCancelable` проверяет чтение и `flush` |
| Неудачная сетевая финализация оставляла распакованные файлы | Гигабайты мусора | Папка удаляется |
| Архивация: плитки удалялись до сжатия, при **ошибке** не возвращались | Игра на месте, плиток нет | Возврат плиток при ошибке; проверка 7z до начала |
| Удалённые с диска игры оставались в библиотеке | «Призраки» в списке | Пересканирование убирает пропавшие |
| Недораспакованная `game/` при ошибке/выходе | Мусор, путаница типа игры | Удаляется в фоновом потоке |
| 4 копии правил имени папки | Расхождения | Одна функция `InstallUtils::sanitizeFolderName` |

### Запуск игр (AppModule)
- Выход из программы в первые ~30 с после запуска игры **ронял процесс**
  (поток ожидания не видел остановку, `QThread` уничтожался работающим).
- Повторный запуск игры: обработчик старого потока обнулял указатель нового →
  то же падение при выходе.
- `AppController::shutdown() const` скрывал `IModule::shutdown()` — модуль не
  получал завершения, и при выходе во время игры **панель задач Windows оставалась
  скрытой**. Метод переименован в `quitApplication()`, добавлено настоящее завершение.

### Ядро и утилиты
- `ModuleHost`: при превышении 8 с остальные модули **пропускались** (эмулятор
  Android TV мог остаться запущенным, хуки клавиатуры, журнал не сбрасывался).
  Теперь завершаются все модули, превышение только логируется.
- Три модуля создавались без родителя (деструкторы не вызывались).
- `SevenZip`: падение 7z считалось успехом → после «успешной» архивации удалялась
  `game/` (**потеря игры**). Теперь ошибка; текст stderr — в журнал.
- `LlamaClient`: глобальный бэкенд llama.cpp освобождался одним клиентом, пока
  второй работал; обработчик журнала становился висячим указателем.
  Отмена во время загрузки модели терялась (выход ждал всю генерацию) —
  теперь загрузка прерываема, флаг сбрасывается только новой задачей.
- `GameInfoModule`: модель (~4.5 ГБ) оставалась в **видеопамяти** до выхода из
  программы — игры получали меньше VRAM. Теперь выгружается после генерации.
- Журнал: ротация только при старте → при работе неделями файл рос без предела.
- Уведомления: постоянное Info-уведомление пропадало, если его вытесняла ошибка.

### Медиа, караоке, Android TV
- `GameMediaModule`: отмена загрузки могла обратиться к уже удалённому загрузчику.
- Трейлер: падение ffmpeg и нехватка места при скачивании давали битое видео

- Обложки и WAV караоке: запись без проверки — обрезанный WAV считался готовым

- Android TV: «добивание» эмулятора через 6 с после выхода могло убить **новую**

# Часть 4 — Android TV, Karaoke, Updater, производительность

## Проверка
- Компиляция: Linux и Windows (MinGW) — 0 ошибок и предупреждений.
- Тесты `tests.pro` — все проходят, многопоточные — под ASan/UBSan чисто.
- **Updater прогнан сквозными сценариями** на поддельной установке (Linux,
  настоящая распаковка 7z): минорное и мажорное обновление, архив без exe,
  неверная контрольная сумма — 19/19. Исходная версия на тех же сценариях
  заменяла рабочую установку архивом без `MediaStation.exe`.

## Updater
- Контрольная сумма архива считается в фоновом потоке: на многогигабайтном
  архиве окно больше не помечается Windows как «Не отвечает».
- Паузы `msleep(3000)` и `msleep(500)` заменены таймерами.
- Нажатие «Отмена», попавшее в очередь до скрытия кнопки, могло сработать
  посреди замены файлов и удалить `MediaStation_New_*`, которую в этот момент
  переносят на место установки. Теперь кнопки работают только в состоянии ошибки.

## Android TV
- **Навигация пультом**: каждое нажатие запускало в Android отдельную JVM
  (`input keyevent`, сотни мс); при удержании кнопки команды копились, и меню
  «уезжало» после отпускания. Теперь нажатия, пришедшие во время выполнения
  предыдущей команды, уходят одной командой, очередь ограничена 8 нажатиями.
- Повреждённый `profiles.json`: резервная копия с отметкой времени (раньше при
  существующем `.bak` профили терялись без копии).

## Нейросети и геймпады
- `GameInfoModule`: создание/чтение `LlamaClient` защищено тем же мьютексом,
  что и выход из программы (гонка между фоновым потоком и `shutdown()`).
- Геймпады: опрос DS4Windows запускал до 21 процесса каждые 5 с. Имя, MAC и тип
  подключения кэшируются; батарея обновляется раз в 30 с. При одном геймпаде —
  4 процесса за опрос вместо 9, при четырёх — 4 вместо 24.

## Прочее
- Karaoke: временный `vocals_16k.wav` удаляется и при ошибке.
- `SteamAppList`: флаги, читаемые из разных потоков, — атомарные.

## Осознанно не изменено
- Очередь для одновременной работы двух нейросетей: при нехватке видеопамяти
  `LlamaClient` уже переходит на процессор (медленнее, но без сбоя), а общая
  очередь добавила бы риск зависания при выходе.
- `SteamAppList` держит всю базу Steam в памяти после первого запроса описания.
  Без реального размера `applications.json` менять вслепую не стал.
- Фоновые задачи `InstallManager` (поиск exe, проверка зависимостей до 30 с) при
  выходе не ожидаются: ждать их хуже, чем крошечное окно гонки.
- Updater остаётся синхронным при переносе файлов (с `processEvents`) —
  полный перевод на конечный автомат без проверки на Windows рискованнее.

## Проверить на Windows (дополнительно)
1. Android TV: удерживать стрелку на пульте 2–3 с, отпустить — меню
   останавливается сразу, без «хвоста».
2. Обновление: окно Updater не «зависает» на этапе «Проверка архива».
3. Геймпад: подключение/отключение видно за ~5 с, заряд обновляется.

# Часть 7 — по журналу и снимкам от 05.11

## Android TV не запускался
По новому журналу причина видна: Android загружается за 25 с (эмулятор пишет
«Boot completed in 24564 ms»), но adb получает «device unauthorized» — устройство
не принимает ключ adb-сервера. MediaStation ждал `sys.boot_completed` через
adb 5 минут, затем закрывал эмулятор.
- adb-сервер теперь запускается с `ADB_VENDOR_KEYS` — предлагает устройству
  все найденные ключи (`%USERPROFILE%\.android\adbkey`, ключ в папке AVD,
  `ANDROID_USER_HOME`), а не только свой.
- Ключ, который отправляет эмулятор, сверяется с `adbkey.pub`; при
  несовпадении — предупреждение в журнале с перечнем проверенных файлов.
- Если эмулятор сообщил о загрузке, а adb всё ещё «unauthorized» (16 с) —
  Android TV показывается без adb, а не висит 5 минут. Пользователь видит
  уведомление: кнопки пульта через adb могут не работать, помогает «Очистить
  данные» в профиле (в старых данных Android сохранена авторизация другого
  ключа).
- Таймаут загрузки больше не записывается как «эмулятор упал».
- В основной журнал попадают только настоящие ошибки эмулятора (`ERROR`,

# Часть 9 — системный аудит (тормоза, оверлей, запуск игр, меню)

## Тормоза после караоке и фриз при открытии страницы игры
- **Утечка экранов (главная причина).** Экраны создавались `createObject()` и
  клались в StackView готовыми, а StackView уничтожает только то, что создал
  сам. Каждый закрытый экран оставался жить скрытым: со своими MediaPlayer
  (трейлер на странице игры продолжал крутиться по таймеру), таймерами и
  подписками на модули. Чем больше открытий — тем сильнее тормоза.
  Теперь `Main.qml` уничтожает экран после ухода со стека; стенд проверяет,
  что после возврата на главный живых экранов 0.
- **Плееры создаются по необходимости.** Караоке — когда трек готов (раньше
  два MediaPlayer с аудиовыходами при каждом входе). Страница игры — через
  0,9 с после открытия и только если есть трейлер (создание плеера и
  открытие файла шли во время анимации перехода → фриз).
- **Эффекты не пересчитываются каждый кадр.** 28 эффектов (размытый фон на
  весь экран, тени, свечения плиток, маски обложек) были без `cached` и
  считались заново на каждом кадре, а дымка перерисовывает окно 30 раз в
  секунду. Теперь `cached: true`; невидимые свечения (opacity 0) не рисуются.
- **Дымка** останавливается, когда её не видно: во время игры, при показанном
  Android TV, когда окно неактивно или дымка выключена.
- **Опрос геймпадов на паузе во время игры** (каждые 5 с — 4+ запуска
  DS4WindowsCmd.exe, отнимали процессор у игры).
- **Сторож отзывчивости:** если интерфейс завис дольше 0,35 с, в журнал
  пишется `[UI] interface was unresponsive for N ms (screen: …)`; смена
  экранов — `[UI] screen: …`. Следующий журнал покажет, остались ли фризы и где.

  игру и выходит (Steam-версии, лаунчеры, `game.exe → game_x64.exe`), раньше
  это считалось закрытием игры: медиацентр всплывал поверх запущенной игры
  или запуск считался неудачным. Теперь отслеживается любой процесс из папки
  игры (до 5 переключений), окно ищется и у них.
- **Панель задач всплывала поверх игры через 20 с** — сторож запуска
  возвращал её, не проверяя, что игра идёт. Теперь он выключается, когда

- **Растягивание окна на весь экран** — только для большого окна (игра в
  оконном режиме). Раньше растягивалось первое найденное окно — заставки и
