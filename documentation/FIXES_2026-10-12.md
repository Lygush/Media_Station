# MediaStation — исправления (12.10.2026)

Архив содержит **только изменённые и новые файлы** с путями от корня репозитория —
распакуйте поверх проекта с заменой. Полный diff — в `mediastation_fixes.patch`
(`git apply mediastation_fixes.patch` в чистом клоне).

Проверка: все `.cpp` из `MediaStation.pro` синтаксически проверены clang'ом под
target `x86_64-w64-mingw32` с заголовками Qt 6.8 + Windows SDK (mingw-w64),
`moc` прогнан по всем заголовкам с `Q_OBJECT`, сделан прогон clang-tidy
(bugprone + static analyzer). Не проверялся только `G72BatteryModule.cpp`
(нужны заголовки C++/WinRT). Реальный запуск эмулятора на Windows я сделать не мог —
см. раздел «Что проверить у себя».

## 1. Android TV (эмулятор) — основная проблема

### Почему эмулятор не запускался / «висел» на загрузке

| # | Причина | Исправление |
|---|---------|-------------|
| 1 | `setup_android_sdk.bat` создавал AVD в `<app>\android-tv\avd`, а приложение ищет его в `<app>\tools\android-tv\avd`. Приложение не находило AVD и создавало «свой» `config.ini` из трёх строк — без `hw.cpu.arch`/`abi.type`, эмулятор считал образ ARM-овым и не стартовал. | Скрипт создаёт AVD в `tools\android-tv\avd` и переносит старый. Приложение при пустом основном каталоге берёт старый (`resolveAvdHome`). `config.ini` теперь дополняется всеми обязательными ключами из `source.properties` образа (abi, arch, tag, API, плотность, клавиатура/D-pad и т.д.). |
| 2 | `ANDROID_EMULATOR_HOME` указывает на папку AVD, а ключ adb лежит в `%USERPROFILE%\.android`. На production-образах устройство оставалось `unauthorized`, `getprop sys.boot_completed` не отвечал → «Boot timeout». | `adbkey`/`adbkey.pub` копируются в домашнюю папку эмулятора после `adb start-server` (тогда ключ гарантированно уже создан). |
| 3 | Все adb-команды шли без `-s`. При любом втором устройстве/эмуляторе (или «зомби»-эмуляторе) — `more than one device`, загрузка не детектировалась, клавиши уходили не туда. | Эмулятор стартует с `-port` (первая свободная пара 5554…5584), все команды — `adb -s emulator-<port>`. |
| 4 | Lock-файлы AVD на Windows — **папки** (`*.lock\pid`), а удалялись только файлы → после падения «AVD is already in use». | Удаляются и папки, и файлы (`removeAvdLocks`). |
| 5 | При ошибке до старта (нет emulator.exe и т.п.) `booting` оставался `true` навсегда — плитка с анимацией загрузки и кнопка не реагировали до перезапуска приложения. | Единый `failLaunch()` возвращает UI в исходное состояние. Проверка наличия emulator/adb/образа ещё до старта, понятный статус. |
| 6 | Таймаут загрузки не убивал эмулятор, окно оставалось висеть. | По таймауту (5 мин) дерево процессов эмулятора завершается. |
| 7 | Опрос загрузки каждые 2 с запускал новый adb, даже если прошлый ещё не ответил (до 10 с) → пачки процессов adb; повторные «1» давали двойной `bootCompleted`. | Один запрос за раз, защита от повторного срабатывания. |

### Окна и переключение

* Окно эмулятора искалось по подстроке `"Emulator"` в заголовке **любого** процесса:
  перехватывались окна Dolphin/PCSX2/других эмуляторов, их PID записывался как PID
  Android TV, и при остановке **убивался чужой процесс**. Теперь окно засчитывается,
  только если его процесс входит в дерево запущенного `emulator.exe`
  (`emulator.exe → qemu-system-*.exe`), заголовок — `Android Emulator - <avd>:<port>`;
  через 15 с есть запасной поиск самого большого окна этого дерева.
* `killEmulatorTree` убивал только прямых детей — теперь всё дерево, снизу вверх.
* После закрытия эмулятора не сбрасывались HWND/PID — следующий запуск цеплялся к
  мёртвому окну. Теперь состояние сбрасывается в `onEmulatorFinished`.
* MediaStation после первого же запуска Android TV навсегда оставался `TOPMOST` —
  **окна запущенных потом игр оказывались под MediaStation (чёрный экран)**.
  TOPMOST теперь включается только на время сессии Android TV и снимается при
  закрытии эмулятора и при запуске игры. В `main.cpp` убран бесполезный
  `WS_EX_TOPMOST` через `SetWindowLongPtr`.
* Смена стиля окна эмулятора не применялась без `SWP_FRAMECHANGED` (оставалась рамка).
* Если переключение на эмулятор не удалось (окно не найдено, эмулятор закрылся во время
  затемнения) — экран оставался чёрным. Теперь всегда приходит
  `emulatorRestoringMediaStation` и QML убирает затемнение.
* Escape открывал оверлей Android TV, даже когда эмулятор работал «за кадром», а
  пользователь был в меню MediaStation. Новое свойство `AndroidTV.active`.
* Прозрачность MediaStation при открытии/закрытии **игрового** оверлея меняется
  только если эмулятор реально показан.

### Ввод с пульта

* На каждую клавишу запускался новый `adb.exe` → задержка в сотни мс и очередь
  процессов при удержании кнопки. Теперь один постоянный `adb shell`, команды
  пишутся в stdin (при обрыве перезапускается сам, есть запасной путь).
* «Избранное» было замаплено на 268 (`DPAD_UP_LEFT`) — исправлено на `KEYCODE_BOOKMARK` (174).
* Клавиши уходят в эмулятор только когда он показан.

### Прочее в модуле

* Время/часовой пояс: `settings put global auto_time 0` **отключал** автосинхронизацию
  времени, а `service call alarm` с захардкоженными номерами транзакций работает не на
  всех версиях Android. Теперь эмулятор получает `-timezone <IANA>` хоста, время он и
  так берёт с хоста.
* Блоклист `/etc/hosts`: `push` без root всегда падал. Теперь только при
  `writableSystem`, через `adb root → wait-for-device → remount → push /system/etc/hosts`;
  на production-образах — понятное сообщение в логе. Каталог для `hosts.tmp` создаётся.
* `-no-boot-anim` передавался всегда, игнорируя настройку профиля.
* `adb kill-server/start-server` выполнялись в `QThread`, захватывавшем `this`
  (мог пережить модуль при выходе) — теперь полностью асинхронно через `QProcess`.
* Убраны блокирующие `waitForStarted` (dnsproxy) и `processEvents` (реентерабельность).
* При каждом запуске создавался новый `QProcess` эмулятора без удаления старого со
  старыми связями — утечка и двойные обработчики.
* `QVariant::type()` (устарело в Qt 6) → `typeId()`; ручные значения таймера/латентности
  читаются корректно и из строк.
* `system.img.qcow2`: учтён суффикс `(actual path: …)` в выводе `qemu-img`, сравнение
  путей без учёта регистра; при пересоздании удаляется и снапшот.
* Лог `Android_TV.log` больше не обнуляется при повторном открытии в той же сессии;
  logcat пишется с правильным `-s`, а `terminate()` (не работает для консольного
  adb на Windows) заменён на `kill()`.

### Профили

* `getProfile()` не возвращал `displayName` → в настройках «Системный образ» был пустым.
* После «Добавить профиль» открывался активный профиль, а не созданный.
* Профиль из «Обзор…» сохранял путь к **файлу** (`file:///…/system.img`) вместо папки
  образа — эмулятор не находил образ. Теперь C++ сам нормализует путь
  (папка, относительно приложения, если внутри него).
* Имя AVD из названия профиля могло содержать кириллицу/пробелы (эмулятор такое не
  принимает) и совпадать у двух профилей (общий диск). Теперь — ASCII и уникальное.
* Повреждённый/пустой `profiles.json` или несуществующий `activeProfileId` → не было
  активного профиля и «молчаливый» отказ запуска. Теперь создаётся профиль по умолчанию
  (с автоподбором установленного образа), битый файл сохраняется как `.bak`.
  Запись через `QSaveFile`.
* Пока эмулятор работает, нельзя сменить активный профиль и очистить его данные
  (`profileManager.locked`).
* Переключатели «Аудио таймер» и «DSound latency» присваивали `checked` и рвали
  биндинг — при переходе на другой профиль показывали чужое значение.
* «Используемое место» не обновлялось после очистки данных.
* Страница **«Общие»** в настройках Android TV была заглушкой («Common settings
  placeholder») — теперь: состояние эмулятора / ошибка последнего запуска,
  «Запустить» / «Остановить», размер пользовательских данных и «Сбросить данные».

### `external_tools/setup_android_sdk.bat`

* AVD, `config`, `blocklists` — в `tools\android-tv\…` (как ждёт приложение), перенос
  AVD из старого места.
* Лицензии: одного `echo y` недостаточно — подаётся 30 подтверждений, явный `--sdk_root`.
* Убраны дописывания `hw.*` в `config.ini` (давали дубликаты ключей).
* CRLF и только ASCII (метки `goto` в `.bat` с LF-переводами строк работают ненадёжно).

## 2. Остальные модули (второй проход — построчное ревью)

### Запуск игр и установка (TileModule, AppModule)

* **`launch.ps1`** (генерируется для каждой игры):
  - писался в UTF-8 **без BOM** — Windows PowerShell 5.1 читает такой файл как ANSI,
    и игра в папке с кириллицей «не находилась». Теперь UTF-8 с BOM;
  - апостроф в пути (`Assassin's Creed`) ломал синтаксис скрипта — экранируется;
  - `[` `]` в имени папки трактовались как шаблон — везде `-LiteralPath`;
  - при ошибке `Start-Process` PID-файл не писался, и GameWatcher ждал 30 с.
    Теперь всегда пишется `0`, а GameWatcher на `0` сразу сообщает об ошибке.
  - ⚠ Скрипты **уже установленных** игр перегенерируются только при смене exe
    (или переустановке).
* **InstallManager**: при ошибке копирования оставалась полупустая папка игры; при
  выходе во время установки — тоже. Имя приложения из exe (PowerShell) приходило в
  OEM-кодировке («кракозябры» вместо кириллицы). Фоновые задачи больше не обращаются
  к удалённому модулю при закрытии.
* **TileManager**: удаление ярлыков игры удаляло только первый ярлык на экране;
  повреждённый `structure.json` молча затирался при первом сохранении (теперь
  сохраняется копия `.corrupted_<дата>`); восстановление ярлыков после отмены
  архивации создавало в `structure.json` «экраны» с мусорными ключами.

### Библиотека игр (GameLibraryModule)

* В `game_info.json` сохранялись служебные поля (`_archiveProgress`, `available`,
  `tileCount`…) — после перезапуска счётчик ярлыков был устаревшим. Запись теперь
  атомарная (было `remove` + `rename`).
* Можно было удалить игру, пока 7z её архивирует/распаковывает, или запустить
  архивацию и распаковку одной игры одновременно.

### Сеть (NetworkModule)

* **Use-after-free** при приёме архива: после ошибки записи/отключения клиента код
  продолжал работать со ссылкой на удалённое состояние клиента.
* Отмена установки во время распаковки удаляла папку, в которую 7z продолжал
  писать; распаковку теперь можно реально прервать.
* Лишние байты после архива дописывались в архив.
* Отправка логов: весь архив читался в память кусками по 2 МБ на каждое событие
  `bytesWritten`; отмена не останавливала упаковку; повторный поиск серверов
  плодил обработчики.

### 7-Zip (tools/SevenZip)

* Прогресс 7z перерисовывается через `\b`, а разбор шёл по `\n` и брал первое
  значение в порции — прогресс сильно отставал. Поиск 7z в PATH не работал.

### Описание игр и LLM (GameInfoModule, LlamaClient)

* **Битая кириллица в описаниях** (символы «�»): токен модели может содержать
  половину UTF-8-символа, а декодировался каждый токен отдельно.
* Если пользователь уходил со страницы игры, не выбрав совпадение в базе Steam,
  фоновый поток ждал **вечно**, и все следующие запросы описаний отклонялись.
  Теперь при уходе выбирается «Пропустить», плюс таймаут 5 мин.
* Если `tools/applicationslist/applications.json` отсутствует или повреждён —
  загрузка «висела» на этапе «База данных» навсегда (SteamAppList ждал успешной
  загрузки, которой не будет).
* При обрезке длинного промпта отрезался конец вместе с заголовком ответа
  ассистента — модель получала «битый» диалог. KV-кэш не очищался после ошибки.
* При выходе во время генерации модель выгружалась, пока поток ещё ею пользовался.
* Короткие поля (жанр, год…) уходили с id другой игры, если совпадение было найдено
  автоматически. Сравнение названий с кириллицей всегда давало 0 (`\w` без Unicode).

### Обложки и трейлеры (GameMediaModule)

* **Загрузка выполнялась в GUI-потоке**: обработчик `QThread::started` был привязан
  к объекту в главном потоке, поэтому интерфейс замирал на всё время скачивания.
* При выходе во время загрузки `QThread` уничтожался работающим (падение).
* Трейлер брался в HLS-формате даже если есть обычный mp4 — без ffmpeg трейлера не
  было вовсе. При отмене ffmpeg результат приходил дважды.
* HTTP-запросы теперь прерываются по отмене сразу, а не по окончании (до 30 с).

### Караоке

* После «Отмена» экран навсегда оставался в состоянии обработки (не было сигнала).
* ffmpeg не прерывался отменой (до 2 мин) и падал по таймауту на длинных треках.
* Whisper не прерывался отменой до конца распознавания; слова с кириллицей
  собирались из кусков UTF-8 и портились.
* Поиск текста на lrclib.net без TagLib (нет альбома/длительности) **всегда**
  завершался ошибкой — добавлен поиск через `/api/search`.
* Недописанные дорожки после ошибки выглядели как готовый кэш; WAV-ридер мог читать
  за пределами буфера.

### Прочее

* **Логи**: `MediaStation.log` рос бесконечно — ротация на 10 МБ; предупреждения и
  ошибки Qt (`qWarning`, ошибки QML) теперь тоже пишутся в файл.
* **AtomicFile**: запись через `QSaveFile` вместо `remove` + `rename`.
* **Уведомления**: одинаковые сообщения больше не копятся в очереди десятками.
* **Джойстик**: профиля `XInput` в DS4Windows нет (Default — это X360), поэтому
  XInput-игры оставались на профиле DS4; папка DS4Windows ищется и как
  `tools/DS4Windows`, и как `tools/DS4-Windows` (так она названа в репозитории).
* **UpdateManager**: во временную папку копировалась вся `tools` (Android SDK, JDK,
  образы — гигабайты). Теперь только 7z.
* **Updater**: переносился только AVD `MediaStation_TV`; теперь все профили и ключи adb.
* **`main.cpp`**: модули удалялись раньше QML-движка (падение при выходе); убран
  жёсткий путь `C:/Qt/6.10.2-msvc-full/qml`.
* **Ярлыки не-игр** (ссылки, `.exe`) затемняли экран и прятали панель задач на 20 с.
* Отсутствующая иконка `ic_karaoke.png`, перевод `lib_menu_regenerate_metadata`,
  101 из 102 кадров анимации загрузки, кнопка «Поиск» пульта → библиотека,
  `-ldwmapi`, регистр пути `Updater/Updater.pro`, путь в тесте G72Battery.

## 3. Что проверить у себя (Windows)

1. Запустить `external_tools\setup_android_sdk.bat <папка сборки>` (или перенести
   `android-tv\avd` в `tools\android-tv\avd` вручную — приложение справится и само).
2. Собрать, нажать плитку Android TV. Ход запуска — в `logs\Android_TV.log`:
   строки `Console port …`, `emulator -avd …` (полная командная строка),
   `AVD config.ini patched/created`, `WinEvent: emulator main window`, `sys.boot_completed = 1`.
3. Esc / Menu на пульте → оверлей → «Выход» — эмулятор должен закрыться, MediaStation
   стать обычным окном (запустите после этого игру — она должна быть поверх).
4. Если эмулятор всё равно падает при старте — пришлите `logs\Android_TV.log`: там теперь
   весь вывод эмулятора и точная командная строка.

## 4. Известные ограничения (не исправлял)

* `dnsproxy` запускается на порту 5300, но эмулятор его не использует (`-dns-server`
  принимает только адрес, порт 53). Оставлено как есть, помечено в коде.
* `modules/GigaAM/GigaAmWrapper.*` не подключены в `.pro` и нигде не используются.
* Whisper в караоке жёстко настроен на русский (`language = "ru"`) — для песен на
  других языках стоит поставить `"auto"`; решил не менять без вашего решения.
* G72Battery сначала ищет пульт по зашитому MAC-адресу, затем по имени «G72».
* JoystickModule: если закрыть приложение в первые секунды, пока DS4Windows
  запускается, фоновый поток может обратиться к уже удалённому модулю (редкий случай,
  требует переделки на токен отмены).
* QML проверен только статически (ссылки на компоненты, ресурсы, API модулей,
  переводы) — `qmllint` на этой машине недоступен.
* Юнит-тесты в `tests/` устарели относительно кода (пути, зависимости) и в
  `tests.pro` подключён только один — нужна отдельная ревизия.
* Прозрачность MediaStation над эмулятором основана на `WS_EX_LAYERED` +
  `LWA_ALPHA`. Если на какой-то видеокарте MediaStation остаётся непрозрачным при
  показе эмулятора, попробуйте переменную окружения `QT_D3D_NO_FLIP=1`
  (отключает flip-model swapchain Qt, с которым layered-окна дружат плохо).
