# Правки 07.11.2026 (4) — ввод в Android TV через gRPC эмулятора

Проверено: компиляция Windows-ветки и сверка импортов; тесты
`tst_emulator_grpc` (7/7) — клиент против **настоящего** gRPC-сервера
(grpcio) по `emulator_controller.proto` из пакета эмулятора,
`tst_androidtv_console` (10/10) — модуль целиком: gRPC → проверка getevent →
нажатия, и переход на запасные пути. **На медиацентре не проверялось.**

## Почему gRPC

Образ `android-tv` — с Google Play, root нет: `sendevent` невозможен,
консоль эмулятора 36.4 нажатия не доставляет, оставался `adb input keyevent`
(JVM в госте на каждое нажатие). `sendKey` в gRPC идёт тем же путём, что
клавиатура окна эмулятора; этим каналом пользуется Android Studio.

## Как сделано

- **`EmulatorGrpcClient`** — без библиотек gRPC/protobuf и без Qt GRPC:
  unary-вызов gRPC = HTTP/2 POST (`QNetworkAccessManager`, h2c без TLS) с
  телом «флаг + длина + protobuf»; `KeyboardEvent` и `EmulatorStatus`
  кодируются вручную. Сборка (qmake) и зависимости не меняются. Есть
  `sendText` для будущего ввода текста.
- Эмулятор запускается с `-grpc <порт> -grpc-use-token` (порт от 8554,
  авторизация — токен консоли `.emulator_console_auth_token`).
- При показе ТВ — `getStatus` (до 5 попыток); на первом нажатии — та же
  проверка через `getevent`, что у консоли. Не дошло — запоминается для этой
  сборки эмулятора, дальше запасные пути.
- Через gRPC: стрелки, OK (`KEY_ENTER`), «Назад», «Домой». «Меню», «Поиск» —
  старым путём.
- Порядок путей: gRPC → `sendevent` → консоль → `adb input keyevent`.
- **Если эмулятор не поймёт флаги** `-grpc` и не запустится: в журнале
  ошибка про `-grpc`, программа запомнит это для сборки эмулятора —
  перезапустите ТВ, он стартует без gRPC.

## Строки журнала `Android_TV.log`

- `[Input] gRPC :8554 ready (emulator …)` — интерфейс отвечает;
- `[Input] gRPC probe: OK, keys reach Android — fast input (no JVM)` — ввод
  через gRPC работает;
- `[Input] gRPC unavailable (…)` / `gRPC input disabled (…)` — причина в
  скобках, работают запасные пути.
