## 1. Сохранность данных

### 1.1 `game_info.json` — единое хранилище (`tools/GameInfoStore.*`, новое)
Раньше файл писали 5 мест, каждое «прочитать → изменить → записать целиком»,
без общей блокировки; кто писал вторым, затирал поля первого.

- `GameInfoStore`: `read`, `update` (только переданные поля, `Null` = удалить),
  `modify` (изменение свежей копии под мьютексом), `write`. Запись — через `AtomicFile`.
- Переведены на него:
  - `GameInfoModule::saveToGameInfo` — только поля описания;
  - `GameMediaModule::saveToGameInfo` — только `coverPath/backdropPath/trailerPath/mediaFetched`;
  - `GameLibraryModule::writeGameInfo` — перезаписывает только свои поля
    (`id, name, type, executablePath, installPath, iconPath, tileLocations,
    installDate, archivePath, sizeCached, legacyNoMetadata`); остальные берёт из
    файла и из памяти — только если в файле их нет. Служебные поля
    (`_*`, `available`, `tileCount`, `archiving…`, `archivePending`) в файл не пишутся.
    `readGameInfo` — через хранилище;
  - `InstallManager`: `inputTypes` после анализа зависимостей и `executablePath`
    в `updateLaunchExe` — точечные `update`;
  - `InstallUtils::writeGameInfoFile` — при переустановке в ту же папку
    обновляет установочные поля, а описание/обложки/трейлер сохраняет
    (медиа — только если файлы на месте; иначе поле удаляется и медиа
    скачаются заново). Найденный ранее `inputTypes` не сбрасывается;
  - `TileManager::readGameInfo` и подстановка обложки в плитки — через хранилище.
- Побочный эффект: `GameLibraryModule::regenerateMetadata` больше не стирает
  описание и обложки.

### 1.2 Относительные пути
- Медиа в `game_info.json` (`coverPath/backdropPath/trailerPath`) хранятся
  относительно папки игры (`launcher/media/cover.jpg`); пути снаружи и URL —
  как есть. При чтении для QML разворачиваются в абсолютные
  (`GameInfoStore::resolveMediaPaths`). Старые абсолютные пути читаются как раньше.
- Плитки в `data/structure.json`: `path`, `icon`, `installFolder` внутри папки
  программы пишутся как `$APP/…`; в памяти и в QML — абсолютные. Явный префикс
  выбран, чтобы не задеть короткие команды вроде `notepad.exe`. Старый файл
  читается как есть, переводится при следующем сохранении.
  Итог: папку MediaStation можно перенести на другой диск — плитки и обложки
  не ломаются.

### 1.3 Архивация игр (`GameLibraryModule`)
- Перед удалением плиток в `game_info.json` пишется `archivePending: [места плиток]`.
  При успехе/отмене/ошибке отметка снимается.
- `recoverInterruptedArchives()` (через 2 с после старта): если программа была
  закрыта или упала во время архивации — удаляет недописанный архив и
  возвращает плитки. Раньше они пропадали навсегда.
- `TileManager`, `createTile`: неизвестное место (у старых установок в
  `tileLocations` лежит id плитки) → плитка ставится на экран «Игры», а не теряется.

### 1.4 Обновление программы
- `Updater`: при крупном обновлении (новая папка) из старой папки переносятся
  недостающие компоненты `tools/` (`mergeMissing`, файлы дистрибутива в приоритете),
  а также `models/` и `logs/`. При ошибке старая папка не удаляется.
- Модель Demucs ищется в `tools/onnxruntime/models/htdemucs.onnx`, старое место
  `models/` — запасное.
- `UpdateManager`: архив обновления удаляется при отказе и при приходе нового;
  при старте чистятся архивы старше суток в `%TEMP%\MediaStation_Update`;
  архив с версией «не новее текущей» удаляется сразу.

### 1.5 Панель задач
- `AppController`: при запуске программы панель задач Windows показывается, если
  осталась скрытой после падения во время игры.

## 2. Android TV — звук и нагрузка

### 2.1 Параметры звука QEMU (`AndroidTVLifecycle.cpp`, `AndroidTVProfiles.cpp`, `ProfileDetails.qml`)
- `QEMU_AUDIO_TIMER_PERIOD` — это частота (Гц). В профиле теперь хранится период
  в мс (4–10 мс), в эмулятор уходит `1000 / мс` Гц.
- Всегда задаются `QEMU_DSOUND_BUFSIZE_OUT=65536` (≈371 мс) и
  `QEMU_DSOUND_LATENCY_MILLIS` (по умолчанию 60, вручную 20–200 мс, не больше 0,6 буфера).
- Миграция профилей (`audioSettingsVersion: 2`): ручные значения из старых
  профилей сбрасываются на «авто» — по старой логике они давали обратный эффект.
- UI: «Период таймера аудио» 4–10 мс (по умолчанию 10), «Запас звука DSound»
  20–200 мс (по умолчанию 60).

### 2.2 Приоритет и энергосбережение процесса эмулятора
- Новый `applyEmulatorProcessPriority(pid)`: `ABOVE_NORMAL_PRIORITY_CLASS` и отказ
  от Power Throttling (`EXECUTION_SPEED | IGNORE_TIMER_RESOLUTION`) — для лаунчера
  и повторно для настоящего `qemu-system-*` (PID из WinEvent-хука и опроса окон).
- Удалены: «буст потоков через 3 с» (повышал потоки лаунчера; поиск аудиопотока
  ни разу не срабатывал) и `timeBeginPeriod(1)` в процессе MediaStation
  (действовал только на сам MediaStation).

### 2.3 Меньше нагрузки во время ТВ
- Убраны `-feature GLDirectMem/GLDMA/VulkanNativeSwapchain` и
  `ANDROID_EMU_MEDIA_DECODER_CUDA_VPX`.
- Убран `adb reverse tcp:80/443/8080/8443` — в программе не использовался.
- Разрешение «авто» ограничено 1080p по высоте с сохранением пропорций экрана.
- logcat по умолчанию выключен; переключатель «Журнал Android (диагностика)»
  в профиле (`diagnosticLogcat`). При включении файл ограничен 64 МБ.
- `JoystickModule`: опрос DS4Windows на паузе, пока ТВ на экране (событие
  `androidtv/shown` из `setEmulatorShown`).
- `WS_EX_LAYERED` у главного окна ставится только на время прозрачности (ТВ /
  оверлей) и снимается при alpha = 255; в `main.cpp` больше не ставится с запуска.

### 2.4 Метрика и прочее
- Раз в 10 минут в журнал: `Audio: total writes N, delayed N (+Δ), underruns N (+Δ)`
  из `dumpsys media.audio_flinger`. По росту чисел можно сравнивать настройки.
- Кнопки громкости в режиме ТВ остаются в Windows (`G72KeysModule` пропускает
  `VK_VOLUME_*` в систему, `AndroidTVInput` их не отправляет).
- `shutdown()`: сначала `adb emu kill` и ожидание до 3 с, потом принудительное
  завершение — меньше шансов испортить `userdata-qcow2`.

### 2.5 Как проверить
1. Запустить ТВ с профилем по умолчанию («авто» = буфер 371 мс, запас 60 мс).
2. Через 30–60 минут посмотреть в журнале строки `Audio:` — прирост `delayed`
   и `underruns` между замерами. Сравнить на слух.
3. Если щелчки остаются — поднять «Запас звука» до 100–120 мс; затем попробовать
   WinAudio вместо DirectSound.
Главный оставшийся фактор — эмулятор работает как фоновое окно под прозрачным
MediaStation (аудит §1.2 B). Эта переделка в данный пакет не входит.

## 3. Караоке

- **Длительность трека** берётся из WAV после ffmpeg (без TagLib раньше всегда 0).
- **Выбор текста на lrclib** (`LrcFetcher`): синхронизированный с длительностью
  ±3 с → любой ±3 с → иначе берётся только текст без тайм-кодов, время слов даёт
  Whisper. То же правило для ответа `/api/get`.
- **Нет интернета** — без повторов: `HttpClient::get(..., int *httpStatus)`
  сообщает код ответа (0 = нет связи); повтор только на 5xx.
- **Проверка синхронизации** тайм-кодов lrclib с дорожкой вокала: подбирается
  сдвиг ±5 с (шаг 40 мс), при котором начала строк совпадают с началами пения;
  применяется, если ≥ 250 мс и улучшение заметное. Пишется тег `[offset:]`.
- **Whisper DTW** — точное время слов: набор голов по имени модели
  (`large-v3-turbo`, `large-v3`, `large-v2`, `medium`); для других моделей DTW не
  включается. `flash_attn` выключается (с ним DTW в whisper.cpp не работает).
  Если инициализация с DTW не удалась — повтор без DTW.
- **Язык песни** — голосованием по трём самым длинным участкам (взвешено по
  длительности); участки, распознанные на другом языке, перераспознаются.
- **Фильтр галлюцинаций** — по целым фразам титров в тексте сегмента
  («редактор субтитров», «продолжение следует», amara.org…), а не по подстроке в
  каждом слове (раньше выкидывались настоящие слова «перевод», «создавал»).
- **Кэш** — `data/songs/<Исполнитель - Название> [отпечаток]`, где отпечаток —
  SHA-1 от размера, первого и последнего 1 МБ файла. Если название потом
  исправили — кэш находится по отпечатку. Старый кэш без отпечатка используется,
  если он полный.
- **Плеер** (`KaraokeScreen.qml`): текст идёт по «минусу» (его слышно всегда);
  раз в 2 с вокал подтягивается к «минусу», если разошлись > 80 мс.
- **Подсветка** текущего слова только цветом (жирный менял ширину и строка «прыгала»).
- **Парсер LRC**: поддержка `[offset:]` и нескольких меток на строке
  (`[00:12.34][00:45.67] текст`).

Замечание: `modules/KaraokeModule/LrcParser.*` нигде не используется (разбор LRC
делается в QML) — кандидат на удаление.

## 4. Сервер (MediaStationServer)

- **Ограничение буфера сокета** (`ServerWindow`, `UpdateTab`): дописывается, только
  пока в буфере < 8 МБ. Раньше на каждый `bytesWritten` добавлялось 2 МБ, и весь
  архив оказывался в памяти. Прогресс доходит до 100 % по фактически
  отправленному, а не по прочитанному.
- **Повторная отправка игры** (`ServerWindow::startSendingArchive`): размер архива
  берётся с диска заново (после ошибки уходил `archiveSize: 0`); если архива
  нет — понятное сообщение.
- **Обновление** (`UpdateTab`): готовый архив не удаляется при сетевой ошибке или
  отказе — можно отправить снова; удаляется после успеха, при новой подготовке
  и при закрытии программы. Номер операции (`m_job`) — поздние результаты
  копирования/хэша после «Отмены» игнорируются (раньше конвейер мог продолжиться);
  папка, в которую ещё копирует фоновый поток, удаляется после окончания копирования.
- **`LogsTab`**: исправлена утечка сокетов при плохом хендшейке; журналы
  сохраняются рядом с программой, а если туда нельзя писать (Program Files) —
  в `AppLocalData`.
- `MediaStationServer.pro`: `QT += concurrent`.
