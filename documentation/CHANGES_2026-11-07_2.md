# Правки 07.11.2026 (2) — плавный оверлей, быстрый ввод через sendevent

Проверено: компиляция Windows-ветки, тест `tst_androidtv_console` (6/6:
разбор `getevent -pl`, ввод через sendevent, консоль, переход на adb).
**На медиацентре не проверялось.**

## 1. Оверлей появлялся рывком

Всё происходило одновременно: смена активного окна (Windows переключает режим
вывода полноэкранного окна эмулятора), первый кадр только что показанного
MediaStation, затемнение и выезд панели — плюс паузы в потоке интерфейса при
повторных попытках смены окна.

- Затемнение (`AndroidTVModule`, `kOverlaySettleMs` = 50 мс) и выезд панели
  (`OverlayScreen.qml`, `PauseAnimation` 50 мс, только для Android TV)
  начинаются через пару кадров после смены активного окна.
- Паузы в повторных попытках `forceForeground` — 1 и 8 мс вместо 15.

## 2. Быстрый ввод без JVM — sendevent (аудит 7а)

Консоль эмулятора 36.4 события не доставляет, поэтому нажатия шли через
`adb input keyevent` — запуск JVM в госте на каждую пачку нажатий (рывки
звука при листании).

Теперь при показе ТВ одним вызовом `adb shell` выполняется
`getevent -pl` (устройства ввода и их клавиши) и проверка, какие
`/dev/input/event*` доступны пользователю shell на запись. Найдено устройство
со стрелками и правом записи — стрелки, OK и «Назад» отправляются утилитой
`sendevent` (нативная, без JVM) прямо в него через тот же постоянный
`adb shell`:

```
sendevent /dev/input/event1 1 108 1;sendevent /dev/input/event1 0 0 0;
sendevent /dev/input/event1 1 108 0;sendevent /dev/input/event1 0 0 0;
```

- OK — `KEY_REPLY` (= DPAD_CENTER), если устройство его знает, иначе `KEY_ENTER`.
- «Домой», «Меню», «Поиск» — по-прежнему `input keyevent` (редкие).
- Не нашлось устройства или нет права записи — консоль эмулятора с
  самопроверкой, затем `adb input keyevent`, как раньше.
- Проверка начинается при показе ТВ, к первому нажатию обычно готова;
  нажатия, пришедшие во время проверки, не теряются.

## Строки журнала `Android_TV.log`

- `[Input] evdev: /dev/input/eventN '<имя>', keys … — sendevent (no JVM)` —
  быстрый путь работает.
- `[Input] evdev: no writable keyboard device — using console/adb` — права
  записи нет, работаем как раньше.
